## 4. `tab:sensitivity` regenerated — 139/139 points

Old file archived as `results/sensitivity_sweep_pre_p08_266feat.csv`.

**All three published conclusions reproduce unchanged**: β safe range 0.10–0.70 (77.8%),
71/115 threshold pairs (61.7%) at 100% DR and 0% FPR, clip ratio insensitive 1.5–4.0. Absolute
AUROC shifted by <0.002 throughout. Detection past β=0.70 degrades slightly *more* sharply on
the corrected data (71.4% at 0.80, 42.9% at 0.90 vs 85.7%/71.4%), which strengthens the case
for the operating point.

### Three bugs found in the sweep's metric extraction

All pre-existing, all in `_extract_detection_rate` / `_extract_fpr`:

1. **`attacker_cid = 1` hardcoded.** Correct for E1 and E4, **wrong for E2**, whose free rider
   is client 2. Every E2 row measured an honest client and reported **0% detection with 53.85%
   FPR** — flatly contradicting Table 2's 100% for the same setting.
2. **`snas_lines[-20:]` fixed tail**, commented "10 rounds × 2 submitted clients in E4". E1 and
   E2 keep all three clients in the window and log 30 records, so their earliest rounds were
   dropped. This is the same bug class Nihal fixed in the attack-magnitude sweep; it survived
   here.
3. `_extract_fpr` inherited the same hardcoded id, so on E2 it counted the real attacker as
   honest and vice versa — inverting both metrics.

**No published number was affected**: the paper cites β and clip from E1 and thresholds from
E4, all of which have attacker = client 1. Fixed by reading the attacker from
`attack_config` and selecting records by run timestamp. The 9 E2 β points were then re-run.

### What the corrected E2 column bought

It turned an unjustified claim into an explained one:

| β | E1 (gradient scaling) DR | E2 (free rider) DR |
|---|---|---|
| 0.10–0.70 | 100% | 100% |
| 0.80 | 71.4% | 100% |
| 0.90 | 42.9% (FPR 7.7%) | 100% |

The free rider is detected at **every** β; gradient scaling only up to 0.70. The β ceiling is
therefore imposed by the **norm-driven** attack alone, because a free rider is anomalous in
direction *and* magnitude simultaneously (either term suffices) while gradient scaling is
invisible to the cosine term and depends entirely on γ=1−β staying large. Previously the safe
range was justified on the experiment where β matters least. `tab:sensitivity` now carries a
row for each.

## 8. Five power outages, nothing lost

Mains failed five times across 20–22 August. Every stage was checkpointed per run with an
atomic temp-file-and-replace, so each outage cost **one run** and the downtime, never an arm.

| # | Hit | Back | State preserved |
|---|---|---|---|
| 1 | ~19:07 20/8 | 21:28 | P1 grid 321/340 |
| 2 | ~22:07 20/8 | 23:23 | P1 grid 326/340 |
| 3 | ~21:05 21/8 | 01:49 | sweep 40/139 |
| 4 | ~12:00 22/8 | 13:13 | sweep 127/139 |
| 5 | ~16:07 22/8 | 17:33 | sweep 134/139 |

`run_sensitivity_sweep.py` originally had **no checkpointing** — it accumulated all 139 results
in memory and wrote the CSV only after the last point, so any interruption discarded the entire
run. Checkpointing was added before launching it; outages 3–5 would each have cost the whole
sweep otherwise.

Two hazards handled during resumes: the non-finite guard added mid-arm was put behind
`SATURATE_NONFINITE_DELTA = False` so the P1-5 arm kept one implementation, and the watcher's
stall detector was fixed to measure from `max(mtime, watcher start)` after it raised a false
alarm on a resumed run.
