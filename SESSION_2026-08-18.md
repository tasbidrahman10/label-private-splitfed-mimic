### Two things to know before you do that

**`requirements.txt` gained `scipy` today.** It was imported by three scripts
(`run_significance_tests.py`, `run_multiseed.py`, `extend_multiseed_to_10.py`) but never
declared, so a venv built from the file alone would have failed at the significance tests —
which is step 2 of the next-steps list. This is the only tracked file changed today.

**`requirements.txt` says plain `torch`, which may not match your GPU.** Plain
`pip install torch` gives whatever CUDA build PyPI defaults to. On the home PC that was
wrong: the RTX 5060 is Blackwell (compute capability 12.0, `sm_120`) and needed an explicit
CUDA 12.8 build:

```powershell

```

Check what the work PC actually needs before assuming:

```powershell
nvidia-smi --query-gpu=name --format=csv
.\.venv\Scripts\python.exe -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_arch_list())"
```

If `cuda.is_available()` is `False` or your card's arch is missing from the list, install
from the matching `download.pytorch.org/whl/cuXXX` index. Everything still runs on CPU, just
slowly. **This is not pinned in `requirements.txt`** — worth fixing if reproducibility on the
GPU build matters.

## 3. Krum collapses to Client 0 — confirmed, with a number

Yesterday's doc predicted this qualitatively. It is now measured on the corrected data:

> **300 of 300 Krum selection rounds chose Client 0 (100.0 %).**
> 30 runs (3 experiments × 10 seeds) × 10 rounds each.

Derivation (read-only, re-runnable):

```powershell
.\.venv\Scripts\python.exe -c @"
import json, collections
sel = collections.Counter(); tot = 0
with open('results/label_private_splitfed/server/server_metrics.jsonl') as f:
    for line in f:
        if 'krum_selected' not in line: continue
        r = json.loads(line)
        if r.get('aggregator') == 'krum' and r.get('krum_selected') is True:
            sel[r['client_id']] += 1; tot += 1
print(tot, dict(sel))
"@
```

The AUROC corroborates it independently: Krum returns 0.9646 / 0.9647 / 0.9646 across three
genuinely different attacks — flat to ±0.0001 — while FLTrust and trimmed mean both move by
0.08+ between E1 and E2. **Krum's output does not respond to what the attacker does**, because
at n=3, f=1 with k=1 the honest scores tie bit-for-bit and `min()` breaks the tie by insertion
order, which is always Client 0 (delay 0 s).
