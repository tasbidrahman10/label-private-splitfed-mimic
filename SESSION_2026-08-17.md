## 3. Headline finding: dropping `los` changed essentially nothing

REVIEW_TRIAGE §3.1 predicted AUROC would fall from 0.965 toward the 0.85–0.90 band that
published MIMIC-IV mortality models occupy. It did not move.

| Cell | New (265 feat) | Published (266 feat) | Δ |
|---|---|---|---|
| SNAS clean | 0.9651 ± 0.0001 (10/10) | 0.9652 ± 0.0004 | −0.0001 |
| SNAS E1 gradient scaling | 0.9613 ± 0.0001 (10/10) | 0.9598 ± 0.0004 | **+0.0015** |
| SNAS E2 free rider | 0.9063 ± 0.0056 (partial) | 0.9050 ± 0.0071 | +0.0013 |

The same thing happened independently at n=6 (0.9481–0.9755 across six clients — see the
note appended to N6_MIGRATION.md Phase 5). Two independent confirmations that **`los` was
never the dominant leak.**

The actual drivers are the two mechanisms in REVIEW_TRIAGE §3.1/§3.2, neither of which is
addressed by dropping one column:
1. **No observation window** — labs aggregated over the whole admission, vitals over the
   whole ICU stay, so a non-survivor's features run through terminal deterioration.
2. **Row-level train/val split** — rows are ICU stays but labels/labs are admission-level,
   so stays from one admission land on both sides with identical feature blocks.

This is already written into the paper (see §5) as an explicit limitation, so the finding is
documented rather than hidden. Favourable read: every *relative* security comparison stands
on identical footing, and the leaky column is gone without any headline number moving.

**One loose end:** seed variance tightened 4× (0.0004 → 0.0001 on clean and E1). Plausibly
`los` was injecting a high-variance signal, but it is a big enough shift that it should be
confirmed rather than explained away before it goes in a table.

## 4. Bugs found and fixed today

All five were pre-existing and would have corrupted an unattended overnight run.

### 4a. P0-4 — FLTrust was a plain mean (`src/sfl/server/app.py`)
Two stacked bugs, both fixed:
- `_compute_fltrust_root_gradient` short-circuited on `state.global_encoder is None`. But
  `/fedavg/open_round` sets that to `None` for the whole window, and aggregation runs after
  the window closes — so it was `None` on **every** call, returning `zeros(1)`, making
  `root_norm ≈ 0`, which made `fltrust_aggregate` fall back to a uniform average. Now falls
  back to `prev_global_encoder`.
- `fltrust_aggregate` compared **absolute weights** to a gradient. Verified synthetically:
  honest/attacker cosines were all ≈0 (shared base dominates); with deltas Δᵢ = θᵢ − θ_ref
  honest ≈0.99 vs attacker ≈0.00. Now aggregates deltas and reconstructs `ref + agg_delta`.
- Third, latent: `root_gradient` was built from `encoder.parameters()` (19,296) while
  submissions flatten the full `state_dict()` (19,488) — a 192-element mismatch from
  BatchNorm buffers that crashed every real aggregation. Now walks `state_dict()` and
  zero-pads buffer slots.

**Paper consequence:** `main .tex` still claims FLTrust "reduces to uniform averaging
because the server cannot compute meaningful encoder gradients." That is now known false —
it was bugs, not architectural incompatibility. **This text must be rewritten** once the
FLTrust cells land.

### 4b. Cumulative delay stacking (`src/sfl/client/multi_runner.py`)
`time.sleep(delay)` ran sequentially inside the submission loop, so each client's delay
stacked on the previous ones. At n=6 with delays 0/3/6/9/12/15 the real submission times
were 0/3/9/18/30/45 s, pushing clients 4–5 past the 25 s window — they were silently dropped
from every round. Invisible at n=3 (max cumulative 15 s < 25 s). Delays are now measured from
window-open.

### 4c. Ephemeral port exhaustion (`src/sfl/client/api.py`)
`requests.request()` was called per API call — a new TCP connection every time. A run makes
~12,000 requests (10 rounds × 3 clients × 200 batches × forward+backward) and each closed
socket holds a Windows port in `TIME_WAIT` ~120 s, exhausting the ~16 k range within two runs
(`WinError 10048`). Fixed with a pooled `requests.Session` + `HTTPAdapter`. Measured: a
2-round run went from consuming ~1,200 sockets to **zero** (2 → 2), and rounds got ~15 %
faster (46 s → 39 s).

### 4d. Orphaned-round race (`src/sfl/server/app.py`, `state.py`)
The round task was fire-and-forget, so `/admin/reset` could not see it. When a client
crashed mid-round its aggregation task kept sleeping through the window; the next run's reset
wiped state underneath it and it woke to `KeyError: 0` at `robust_fedavg.py:111`, tearing down
connections the new run was using — one failure cascaded into all subsequent ones. Now tracked
as `ServerState.round_task` and cancelled before reset.

### 4e. Stale keep-alive connections (`scripts/start_server.py` + `api.py`)
Uvicorn's default `timeout_keep_alive` is **5 s**, but the client idles far longer (25 s async
window, per-client delay sleeps). The server closed pooled connections and the client reused
dead sockets → `ConnectionReset` / `ConnectionAborted`, with **zero** server-side errors,
which is what pointed at the client pool. Fixed both ends: `timeout_keep_alive` now 4× the
async window (≥120 s), plus a connection-level `Retry` on the adapter. Proof: seed 1001 went
from failing 3/3 attempts to succeeding first try.
